# Миграция 3x-ui → Remnawave

Что уже в коде, что осталось сделать руками и в каком порядке.

## Принцип, из которого следует всё остальное

**Ссылки клиентов не меняются.** Ни `/sub/<sub_id>`, ни выданные `vless://`.
Держится это на трёх совпадениях, и каждое надо не потерять:

| наше | в Remnawave | зачем |
|---|---|---|
| `UserVPN.vpn_uuid` | `vlessUuid` | старая ссылка поднимает ту же личность |
| `UserVPN.sub_id` | `shortUuid` | панель раздаёт подписку по тому же адресу, по которому её спрашивает наш прокси |
| Reality-ключ inbound 5 | конфиг ноды | старая ссылка вообще проходит рукопожатие |

Третье — единственное, что копируется руками, и единственное, что нельзя
сгенерировать заново: новый Reality-ключ обесценивает все выданные ссылки.

## Что уже сделано в коде

Всё выключено флагами, ни один запрос к Remnawave не уходит, пока их не включат.

| файл | что |
|---|---|
| `apps/servers/remnawave.py` | клиент API панели на httpx, без SDK |
| `apps/servers/remnawave_client.py` | `RemnawaveVPNClient` — тот же контракт, что у `APIVPNClient` |
| `apps/servers/vpn_client.py` | `vpn_client_for()` — единственное место выбора панели |
| `apps/servers/management/commands/migrate_to_remnawave.py` | перенос клиентов, по умолчанию без записи |
| `apps/subscriptions/views.py` | `/sub/<sub_id>` проксирует в Remnawave, наши заголовки поверх |
| `apps/subscriptions/tasks.py` | `BILLING_PAUSED` — пропуск списания на техработах |

Вызывающий код переведён на `vpn_client_for()` в четырёх местах:
`add_vpn_to_user`, `remove_vpn_user_from_server`, `disable_vpn_user_from_server`,
`api/v1/vpn/views/box.py` (канал конфигурации роутеров — он должен пережить
переключение, иначе платы перестанут обновляться).

Проверка: `manage.py test apps.subscriptions.test_billing
apps.servers.test_remnawave apps.subscriptions.test_remnawave_proxy
apps.subscriptions.test_views apps.vpn.test_legacy_vpn_state
apps.telegram_bot.test_add_key apps.telegram_bot.test_admin_money` — 223 теста.

## Чего не хватает

**Сервер под панель.** Ни один из существующих не подходит:

| хост | CPU | RAM | диск | вывод |
|---|---|---|---|---|
| BOT `72.56.23.226` | 1 | 961 МБ (419 МБ уже в свопе) | 2.8 ГБ свободно из 14 | нет |
| NL `sub.special-wifi.ru` | 2 | 1967 МБ | 44 ГБ свободно | по минимуму проходит, но нельзя |

NL формально проходит порог панели (2 ГБ / 2 ядра / 20 ГБ), и всё равно не
подходит: `darkcore-connection-service` там деплоится через Drone по SSH, то
есть исполнение на этом хосте есть у третьей стороны. Панель держит доступ всех
клиентов сразу — она не может стоять там, где мы не одни. Ноду там ставить
можно: она не хранит ничего, кроме конфига, который ей прислали.

Требования к новому хосту: 2 ГБ RAM, 2 ядра, 20 ГБ диска, Docker с плагином
Compose, домен с сертификатом. Чистый, без сторонних деплой-ключей.

**Точка замера в России.** Блокировки — российские, а мерили мы из NL и
Беларуси. Пока замера из РФ нет, «миграция прошла успешно» проверить нечем.
SSH на relay `201.34.132.118` (Timeweb СПб) закрыт и для `specialops`, и для
`root`. Нужен любой VPS у Timeweb СПб — там же, где узлы, по которым мы
сравниваем.

## Порядок

### 1. Панель на новом хосте

```
curl -o docker-compose.yml https://raw.githubusercontent.com/remnawave/backend/refs/heads/main/docker-compose-prod.yml
curl -o .env https://raw.githubusercontent.com/remnawave/backend/refs/heads/main/.env.sample
sed -i "s/^APP_SECRET=.*/APP_SECRET=$(openssl rand -hex 64)/" .env
sed -i "s/^METRICS_PASS=.*/METRICS_PASS=$(openssl rand -hex 64)/" .env
sed -i "s/^WEBHOOK_SECRET_HEADER=.*/WEBHOOK_SECRET_HEADER=$(openssl rand -hex 64)/" .env
```

`SUB_PUBLIC_DOMAIN` — домен панели с `/api/sub`, без схемы и без слэша на
конце. Пароль Postgres поменять в двух местах: `POSTGRES_PASSWORD` и внутри
`DATABASE_URL`. Наружу ничего не публиковать: сервисы на `127.0.0.1`, снаружи
только реверс-прокси.

Проверка: админка открывается, `GET /api/users` с токеном отвечает 200.

### 2. Нода на NL рядом с 3x-ui

Compose ноды генерирует сама панель (Nodes → создать → «Copy docker-compose.yml»),
сертификат оттуда же кладётся в `SSL_CERT`. `NODE_PORT` закрыть файрволом на
всё, кроме адреса панели.

Порты берём свободные, 3x-ui не трогаем — два xray работают параллельно.
На NL 1138 МБ доступной памяти и нет свопа; нода со своим xray и NestJS съест
около 300 МБ. Перед стартом посмотреть `free -m`, при нехватке — сначала
выключить неиспользуемые inbound-ы 3x-ui.

Проверка: нода в панели online, конфиг доехал.

### 3. Reality-ключ

В конфиг-профиль ноды кладётся `realitySettings` **того же** inbound 5, что
работает сейчас: `privateKey`, `shortIds`, `serverNames`, `dest`. Ключ копируется
с хоста на хост и не проходит ни через чей терминал.

Публичные части того же ключа кладутся в окружение бота — после вывода 3x-ui
читать их будет неоткуда:

```
REMNAWAVE_REALITY_PUBLIC_KEY=
REMNAWAVE_REALITY_SERVER_NAME=
REMNAWAVE_REALITY_SHORT_ID=
REMNAWAVE_REALITY_PORT=443
```

Проверка: тестовый клиент в панели, его ссылка поднимается настоящим `xray`
(не sing-box — он не умеет ни этот Reality, ни XHTTP и даёт ложный FAIL).

### 4. Перенос клиентов

```
REMNAWAVE_API_URL=https://<панель>
REMNAWAVE_API_TOKEN=<токен>
REMNAWAVE_SQUAD_UUIDS=["<uuid отряда>"]
```

```
manage.py migrate_to_remnawave              # отчёт, ничего не пишет
manage.py migrate_to_remnawave --apply      # создаёт клиентов
```

Если панель откажется от `shortUuid` длиной 32 символа или от поля
`activeInternalSquads` — она назовёт поле в теле ошибки, оно печатается.
Имя поля отряда меняется настройкой `REMNAWAVE_SQUAD_FIELD`, без правки кода.

Проверка: число `ACTIVE` в панели равно числу `UserVPN.enabled=True` (сейчас 43).

### 5. Бот

```
REMNAWAVE_ENABLED=true
```

Проверка: выдача, отключение, включение тестового аккаунта видны в панели.

### 6. Подписка

```
REMNAWAVE_SUBSCRIPTION_PROXY_ENABLED=true
REMNAWAVE_SUBSCRIPTION_BASE_URL=https://<панель>/api/sub
```

Прокси отдаёт документ панели, но заголовки срока, названия профиля и
объявления — наши: считает их бот по балансу, и второе число на том же экране
означает два разных срока у одного человека.

Если панель не ответила, запрос уходит по старому пути 3x-ui. Пустой ответ или
502 клиент читает как «серверы пропали» — это ровно авария 2026-08-20.

Проверка: Happ и v2rayNG получают документ панели и подключаются **из России**.

### 7. Переключение и вывод

3x-ui остаётся включённым несколько дней. Выводить не раньше недели без жалоб,
и отдельно решить, что делать с девятью чужими клиентами на inbound 10 и 13:
они не наши, но живые, и вместе с 3x-ui выключатся.

## Списание на время работ

```
BILLING_PAUSED=true
```

Закрытый бот не останавливает списание: доступ у людей работает, а пополнить
баланс негде. Первый, у кого кончатся деньги, отключится и не сможет вернуться.

**Снять вместе с открытием бота.** Каждый день с этим флагом сервис работает
бесплатно, и ничто об этом не напомнит, кроме строки `Billing run skipped` в
логе.

## Откат

`REMNAWAVE_ENABLED=false`, `REMNAWAVE_SUBSCRIPTION_PROXY_ENABLED=false`,
пересоздать контейнеры. Код 3x-ui остаётся в репозитории до пункта 7, поэтому
откат не требует ни ревертов, ни сборки.
