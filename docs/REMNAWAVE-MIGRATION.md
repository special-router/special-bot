# Миграция 3x-ui → Remnawave

**Выполнена 2026-08-21.** Клиентов обслуживает нода Remnawave, 3x-ui остановлен
и снят с автозапуска. Ниже — что именно стоит, чем это проверено и что осталось.

## Принцип, из которого следует всё остальное

**Ссылки клиентов не менялись.** Ни `/sub/<sub_id>`, ни выданные `vless://`.
Держится это на трёх совпадениях:

| наше | в Remnawave | зачем |
|---|---|---|
| `UserVPN.vpn_uuid` | `vlessUuid` | старая ссылка поднимает ту же личность |
| `UserVPN.sub_id` | `shortUuid` | панель раздаёт подписку по тому же адресу |
| Reality-ключ inbound 5 | конфиг ноды | старая ссылка проходит рукопожатие |

Reality-ключ скопирован тот же самый: новый обесценил бы все выданные ссылки.

## Что где стоит

| что | где |
|---|---|
| панель + Postgres + Valkey | NL, `/opt/remnawave`, порты хоста 3100/3101 |
| панель снаружи | nginx `:8843`, серт `sub.special-wifi.ru`, панель в корне |
| нода `NL-1` | тот же хост, `network_mode: host`, xray 26.7.28 |
| конфиг-профиль | `236bceb0-…`, три inbound-а: 8443 tcp, 8080 grpc, 20443 xhttp |
| отряд `SPECIAL` | `53d15551-…`, в нём все три inbound-а |
| админ, API-токен, uuid отряда | файлы 600 в `/opt/remnawave` |

Панель стоит на NL, хотя хост делится с `darkcore-connection-service`, у
которого есть сторонний деплой-ключ. Это осознанный компромисс: отдельного
чистого хоста нет, а оставаться на 3x-ui было дороже. При появлении чистого
хоста панель переезжает, нода остаётся.

## Роли после переезда

Remnawave заменил 3x-ui **как control plane и ядро**. Подписку по-прежнему
собирает наш Django.

Причина не в удобстве. Живая подписка — 14 строк: статус, наши четыре точки и
**девять стран стороннего зеркала** (`sni=cloudrynth.com`). Про зеркала панель
не знает; проксирование `/sub/` на неё вырезало бы у клиента большую часть
списка — ровно авария «серверы пропали» 2026-08-20. Поэтому
`REMNAWAVE_SUBSCRIPTION_PROXY_ENABLED=false` и код прокси оставлен выключенным.

Reality-параметры для сборки ссылок читаются из настроек
(`_configured_params` в `apps/subscriptions/views.py`), а не из API панели.

## Что в коде

| файл | что |
|---|---|
| `apps/servers/remnawave.py` | клиент API панели на httpx, без SDK |
| `apps/servers/remnawave_client.py` | `RemnawaveVPNClient` — контракт `APIVPNClient` |
| `apps/servers/vpn_client.py` | `vpn_client_for()` — единственное место выбора панели |
| `apps/servers/control_plane.py` | выбор источника инвентаря по тому же флагу |
| `apps/servers/remnawave_inventory.py` | инвентарь клиентов и inbound-ов из панели |
| `apps/subscriptions/views.py` | Reality-параметры из настроек; прокси выключен |
| `apps/subscriptions/tasks.py` | `BILLING_PAUSED`; `sync_expiry_times` не идёт в панель |
| `apps/vpn/services/subscription_delivery.py` | выбор пути выдачи ссылки по флагу |
| `apps/servers/remnawave_subscription.py` | сборка ссылки без 3x-ui |
| `apps/monitoring/probes.py` | L0 и канарейка читают действующую панель |

Панель опознаёт пользователя целочисленным `id`; поля `uuid` у неё нет.
`shortUuid` задаётся только при создании — PATCH принимается и молча
игнорируется.

## Мониторинг

L0 — предохранитель «оплатил, доступа нет» — читает инвентарь из панели. Ждёт
двух совпавших чтений подряд и вычитывает все страницы пользователей: неполное
чтение выглядело бы как исчезнувшие клиенты.

`SPECIAL_MONITOR_EXPECTED_INBOUNDS` задаёт числовые id из 3x-ui, которых у
Remnawave нет. Inbound опознаётся **по порту**: порядковый номер в профиле
менялся бы от любой перестановки и поднимал бы `inbound_inventory_drift` на
пустом месте.

Живая проверка 2026-08-21 после переключения: `host`, `l0`, `l1`, `l2` — все
зелёные, `entitled_missing: 0`, канарейка проходит обе ноги до ожидаемого
выходного IP.

`extras: 13` в отчёте L0 — это девять импортированных не-ботовых клиентов плюс
четыре ботовых с балансом ниже тарифа. Не тревога.

## Клиенты вне бота

В 3x-ui жили клиенты, которых бот не знает. Они заведены в панели вручную с
именами `legacy_<inbound>_<…>`, иначе переключение отрезало бы их:

- два grpc-роутера с реальным трафиком (8.9 ТБ и 402 ГБ);
- семь xhttp-клиентов без email и срока.

Запись `shell` на inbound 10 пропущена: её id не UUID, трафик нулевой.

## Что оказалось важным по дороге

**`flow` нельзя отдавать панели на усмотрение.** Если поле не задано, она
выводит его сама: tcp+reality → `xtls-rprx-vision`. Живых клиентов с Vision
было три, и все отключённые; 64 из 67 работали без `flow`, и наш генератор
подписок отдаёт `flow=''` намеренно. Неявный Vision отверг бы **каждую**
выданную ссылку. В профиле проставлен явный `flow: ""` на всех трёх inbound-ах.

Симптом на клиенте — `unexpected eof while reading`, то есть похоже на
поломанный Reality. На деле рукопожатие проходило, отказ был на уровне VLESS:
`account … is rejected since the client flow is empty` в `/var/log/xray/current`
внутри контейнера ноды. Диагностика без этого лога уводит в сторону.

**nginx упирается в `worker_connections`.** После переключения весь Reality идёт
через stream-прокси, по два слота на клиента. Debian-овские 768 исчерпались, и
nginx начал отказывать живым клиентам: 3579 строк `worker_connections are not
enough`. Поднято до 16384 при `worker_rlimit_nofile 65535` и
`LimitNOFILE=65535` в systemd-override.

**Нода хочет `SECRET_KEY` и `NODE_PORT`.** Не `SSL_CERT` и не `APP_PORT`, как в
части документации. Значение — `secretKey` из `/api/keygen`, не `pubKey`. Ошибка
в имени переменной стоила двухминутного простоя при первой попытке.

**Сессионный JWT не работает для `/api/*`** без заголовка
`x-remnawave-client-type: browser`. Долгоживущий токен создаётся полями `name` и
`expiresInDays`.

**Предохранитель выдачи спрятал аварию.** `get_user_access_url` продолжал
собирать ссылку через `XUISubscriptionConnector`, то есть через остановленный
3x-ui. Каждый запрос падал, срабатывал `except`, и клиент получал прямой
`vless://` — одну точку вместо четырнадцати. Ошибок в логе при этом нет, есть
только `Subscription delivery fallback` на WARNING. Правило на будущее: при
смене control plane смотреть частоту этой строки, а не отсутствие ошибок.

## Списание на время работ

```
BILLING_PAUSED=true
```

Закрытый бот не останавливает списание: доступ работает, а пополнить баланс
негде. Первый, у кого кончатся деньги, отключился бы и не смог вернуться.

**Снять вместе с открытием бота.** Каждый день с этим флагом сервис работает
бесплатно, и ничто об этом не напомнит, кроме строки `Billing run skipped`.

## Откат

`REMNAWAVE_ENABLED=false`, пересоздать контейнеры, `systemctl start x-ui`.
Код 3x-ui и его путь в `control_plane.py` остаются в репозитории, поэтому откат
не требует ни ревертов, ни сборки. Он перестанет быть возможным, когда 3x-ui
выведут окончательно.
